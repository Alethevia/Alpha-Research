# 小本金量化研究：2000 美元与 1000% 年收益目标

研究日期：2026-10-12（America/New_York）。

**当前状态：第一阶段研究工具，尚无通过验证的交易策略。**
已完成目标反推、条件情景模拟和实验登记工具；没有运行新的市场回测，
没有连接券商、下单、部署交易服务或证明目标可持续实现。

## 研究问题

在不追加本金、计入交易费、融资费、数据和服务器成本的条件下，寻找可能
将 2000 美元在一个完整年度增长到 22000 美元的可执行策略，并同时评估亏损、
最大回撤、保证金不足和失去继续交易能力的风险。个人所得税单独报告。
一年达到目标、短样本收益年化、连续多年达到目标，是三个不同的结论。

小账户的潜在优势是订单规模小、冲击成本可能较低、能利用容量较小的机会；
需要用实际成交数据证明。最小手数、手续费、数据费和保证金也可能使小账户
更难实施某些策略。仓位规模不能自动产生正期望。

## 采用 OpenAI 公开研究方法的哪些部分

OpenAI 在 First Proof 论文附录 A 描述了：生成种子思路、分别尝试求解、
检查论证与引用、根据发现的缺口修订，再整理结果。附录也说明这套程序化
流程是在原始人工组织的工作之后尝试的。10 月发布的 `openai/math` 包含
验证状态不同的结果，以及部分 Lean 形式化证明和修订历史。

这里借鉴其公开的研究流程；不声称调用了该研究使用的内部未发布模型、
同等算力或完整内部方法。市场收益依赖会变化的分布，不能像固定数学命题
一样用证明助手保证。单元测试验证计算和软件边界，市场数据与前瞻检验
评价交易假说；两个层次都需要。

| 研究环节 | 本项目的对应做法 |
| --- | --- |
| 多个种子思路 | `protocol.json` 中的五项有经济机制的候选假说 |
| 精确问题定义 | 资金、完整年度、净费用、回撤、最小手数、市场权限 |
| 求解 | 每个假说形成明确的信号、仓位、退出、成交规则 |
| 查找反例与缺口 | 未来信息、幸存者偏差、费用、延迟、跳空、逆向选择 |
| 修订 | 每次修改都登记为新试验，保留失败结果 |
| 计算检查 | 可穷举的小例子、财务恒等式、确定性测试 |
| 外部证据 | 冻结规则的时序验证、预留评估和独立前瞻模拟交易 |

这些对应做法是本项目的金融研究设计，不是 OpenAI 官方量化交易配方。

## 目标算术

1000% 收益率是 **11 倍终值**，不是 10 倍。等价恒定复合收益为：

| 周期 | 每期复合收益 |
| --- | ---: |
| 每月，12 期 | 22.1189% |
| 每周，52 期 | 4.7193% |
| 每交易日，252 期 | 0.9561% |
| 每自然日，365 期 | 0.6591% |

假设每笔以当时净值的比例 `f` 冒险，毛盈利为 `b R`，毛亏损为 `1 R`，
每笔往返费用为 `c R`。R 是该笔下单前的风险金额。则：

```
盈利因子 = 1 + f * (b - c)
亏损因子 = 1 - f * (1 + c)
终值倍数 = 盈利因子^胜笔数 * 亏损因子^负笔数
所需胜笔比例 = [ln(11)/N - ln(亏损因子)]
               / [ln(盈利因子) - ln(亏损因子)]
```

这只是固定两点收益模型。实际交易有不固定盈亏、跳空、重叠持仓、
整数手数和无法成交等问题。选一个止盈价，不等于实现相应的平均盈亏比。

例如，全年恰好 500 胜、500 负，`f=1%`、`b=1.5`：

| 每笔额外费用 | 对应当时账户净值 | 期末倍数 |
| --- | ---: | ---: |
| 0 R | 0 | 11.2362 |
| 0.05 R | 0.05% | 6.8222 |
| 0.10 R | 0.10% | 4.1412 |

这些费用是敏感性假设，不是任何券商报价。真实费用需按成交金额、合约数、
点差、资金费和时长计费，再除以当笔风险金额转换为 R。
以上倍数不是回测收益或预测。若每笔风险为 2%，连续 20 笔各亏 1 R，
仅这些亏损已造成约 33.24% 回撤，还未加入费用和超额止损损失。

## 已实现的工具

`target_lab.py`：

- 目标终值、复合收益要求和交易次数/风险比例的反推；
- 二点独立模型的精确二项分布终值概率；
- 固定种子情景模拟，加入成本、胜率下降和胜负聚集的压力情景；
- 分别报告终值、最大回撤和跌到初始资金一半的事件；
- 明确标注所有输入为假设。50% 资金损失不等于破产；该模型不含清算。

`experiment_registry.py`：

- 先登记假说、数据哈希、代码版本、参数、切分、成本和淘汰条件，再记录结果；
- 错误、淘汰和未结束的实验均保留记录；禁止重复覆盖同一试验；
- 哈希链可以发现已有记录的意外改动，不能防止整本重写；仅支持单写入者；
- 检查必要字段与证据类型，不验证字段内容真实、市场可交易或测试集未被看过；
- 此处的试验计数不含其他日志，统计筛选校正仍需合并相关旧试验。

`protocol.json`：五项候选假说及验证计划。它是设计草案，尚未完成参数、
市场和数据窗口的冻结，因此不应宣称“五个策略已经预注册/回测”。

## 运行

从仓库根目录运行，Python 3.10+，无第三方依赖：

```bash
python research/small_account/target_lab.py --paths 5000 --output artifacts/small-account/scenarios.json
python -m unittest discover -s research/small_account -p 'test_*.py' -v
```

已用种子 `20261013` 运行五组、每组 5000 条假设路径，输出为
`example_hypothetical_results.json`。文件内的概率仅在输入假设成立时适用，
不能视为真实策略达标率。模拟抽样误差也不包含模型错误与参数估计误差。

实验登记命令（先编写内容完整的冻结 spec；不能直接传入 `protocol.json`）：

```bash
python research/small_account/experiment_registry.py --journal artifacts/small-account/trials.jsonl register H1-001 --spec artifacts/small-account/H1-001-spec.json
python research/small_account/experiment_registry.py --journal artifacts/small-account/trials.jsonl complete H1-001 --outcome rejected --artifact artifacts/small-account/H1-001-result.json
python research/small_account/experiment_registry.py --journal artifacts/small-account/trials.jsonl inspect
```

Spec 的字段见 `register()`；结果 JSON 必须携带与 spec 相同的 `evidence_type`。
这只是登记功能，没有自动运行策略或自动授予上线资格。

## 下一阶段

1. 确定实际可用账户/品种和用户愿意承受的美元损失与峰值回撤。
2. 核对最小手数、实际保证金、手续费和数据条件，淘汰无法在小账户中执行的品种。
3. 优先把 H1 变成一条简单、完全可复现的基线规则；先冻结规则再取评估结果。
4. 使用实际标的的时间序列与报价测试，再逐项检验其他假说。全部失败也是有效结果。
5. 对通过开发阶段的候选，做时间隔离、未参与选型的评估及锁定规则的前瞻模拟交易。

市场细节未定前不能声称已建成可上线交易系统，也不能据此合理估计十倍收益的现实概率。
对任何候选，都同时报告收益来源、样本不确定性、达到目标的条件及失效方式。
